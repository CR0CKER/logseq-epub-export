**Block references, embeds, and images on Windows.**

## New

- **Block references and embeds:** `((block))` becomes a link to the block, labelled with its text, and `[label](((block)))` keeps your label. `{{embed [[page]]}}` and `{{embed ((block))}}` show the page, or the block with its children, in place. Embeds nest three levels deep; anything deeper, or embedding itself, becomes a link. ([#5](https://github.com/CR0CKER/logseq-epub-export/issues/5))
- **A clue when images fail:** the export log now ends with a "First failure:" line naming the first image that couldn't be read, each address tried, and what came back.

## Fixed

- **Images on Windows:** on file graphs, every image became a placeholder, because the plugin built the image address from the Windows path as-is. Drive letters and network shares now work. ([#4](https://github.com/CR0CKER/logseq-epub-export/issues/4))

## Security

- DOMPurify, which comes in with the Logseq plugin SDK, is raised to 3.4.16 for [GHSA-p98j-92pf-mc4p](https://github.com/advisories/GHSA-p98j-92pf-mc4p), a low-severity DOM XSS. `npm audit` reports no known vulnerabilities.

## Install

1. Download `logseq-epub-export-v0.2.0.zip` below and unzip it.
2. In Logseq: **Settings → Advanced → Developer mode** on, then **Plugins → Load unpacked plugin** and pick the unzipped folder.

If you installed from the Logseq marketplace, update it from Logseq's Plugins page.

## Testing

The live suite passes on Logseq 0.10.15, Logseq 2.0.1 and the OG build: 79 checks, including a new page of block references and embeds on both graph types. The Windows fix is covered by unit tests checked against Node's own path-to-URL conversion; it has not been run on Windows itself.

Full details are in the [changelog](https://github.com/CR0CKER/logseq-epub-export/blob/master/CHANGELOG.md).
